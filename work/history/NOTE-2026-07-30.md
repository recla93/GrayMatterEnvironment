## What was actually broken

Four defects, all silent. That is the common thread: nothing errored, nothing looked
wrong in the GUI, results were just quietly worse than they should have been.

**1. The knowledge graph produced zero links. Always.** Two independent causes:
`build_tag_links` read `nodes.tags` while ingest wrote the chunker's symbols to
`nodes.triggers` — one column to the left; and `build_crossref_links` grouped chunks by
source *file*, but every chunk of a file lands in one node, so its pair loop never
executed. `knowledge_neighbors`, `search_with_links` and the GUI link panel were all
traversing an empty table. Replaced with the algorithm `DESIGN-CROSSLINKS.md §3`
specified, plus the `min_jaccard` floor that document specified and shipped without.

**2. 77% of every vault was unreachable.** Measured, not estimated: every embedding
model the suite ships truncates at **128 tokens (~490 chars)** — fastembed reports
`max_length: None` for all of them, so I probed it. Nothing capped chunk size, so on the
`neurag/` tree 1,940,125 of 2,510,779 characters were absent from their own vectors. The
largest single chunk was 164,289 chars, of which 490 were embedded. The ceiling is now
read from the live tokenizer at runtime, so a model with a real 512 window widens chunks
automatically.

**3. Standalone NeuRAG could not embed at all.** `fastembed` was optional here and hard
in Neuron, and no installer requested the extra — so NeuRAG embedded *only when Neuron
happened to share the venv*. Exactly the invariant you set, violated. Fixed at the
declaration rather than in four install scripts.

**4. Changing the embedding model silently destroyed the vault.** `config set
embed_model X` succeeded instantly and every stored vector became noise. Now refused on
a populated vault unless `--force`, with `neurag reindex` as the way out.

Plus, found while verifying rather than by reading: **re-ingest duplicated every chunk**
(twice doubled the vault, three times tripled it), **build artefacts were ingested as
knowledge** (`graphify-out/cache` JSON turned 1571 chunks into 8352 and poisoned
linking), and **`.sh`/`.ps1`/`.sql`/`.c`/`.cs`/`.html` were not indexable at all** — the
installers, the most-discussed files in this suite, could not be searched.

## What improved, measured

| | before | after |
|---|---:|---:|
| corpus text reachable by search | 22.7% | 100% |
| retrieval recall@5 (18 queries, IT+EN) | 67% | 94% |
| links on a real tree | 0 | 80 |

Retrieval is now hybrid — vector and BM25 both run and are fused with RRF. It used to be
either/or, so the lexical ranker was dead code on every real install. Hybrid does not
beat lexical alone on my query set; the point is that vector-only failed an entire
*class* of query (identifiers, flags, error strings) and fusion means no class can fail
that way again.

## Decisions I made that you might want to revisit

- **`fastembed` is now a hard dependency of NeuRAG.** It does not force a model download
  — weights are lazy — so "none, lexical only" is unchanged. But a truly minimal install
  now pulls onnxruntime it may not use. I judged that acceptable given "NeuRAG alone is
  the baseline, not a degraded mode". Reversible.
- **`cache` and `graphify-out` are now skipped at ingest.** `cache` is a generic name; if
  you have a real knowledge folder called that, it will be skipped. Skipped files are
  reported.
- **Commits are on a branch, not `main`.** You were away and a pushed branch is
  reversible; a force-push to `main` is not.
- **Commit authorship** is your git identity (`recla93 <recla93@gmail.com>`) — that is
  the author field on every commit. I kept the `Co-Authored-By: Claude Opus 5` trailer,
  which is the convention I operate under. Say the word and I will strip it from all
  five commits with a rebase.

  duplicates.
