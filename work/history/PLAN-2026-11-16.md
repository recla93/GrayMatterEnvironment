# Plan — 2026-11-16

> **Status at the end of 2026-11-16** (released: Gray Matter 1.10.0, Neuron
> 6.12.0, NeuRAG 1.9.1). This block is the current state; the sections below
> are the plan as written in the morning and are kept for the reasoning.

## Where things stand

Released and installed:
- Recall: 2 facts, wording shared with the message (`NEURON_FACT_LEX_BONUS`).
- Notes on facts (`#id ↳#id`), the writing client in `source`.
- Use signal from the reply (Stop hook → `confirm`), a gist judged on its full
  text, a `shown` counter beside `confirmed`.
- Installer: a redirected install completes.
- NeuRAG: one embedding model per process; its suite takes 67 s, the gate 3 min.
- An experiment switch for the use rate, **off** (`NEURON_FACT_USE_BONUS=0`).

Measured on real sessions and closed, do not redo without new data:

| Idea | Result |
|---|---|
| Calibrated score from similarity signals | does not predict use (AUC 0.51 out of sample) |
| Newest progress facts at session start | 2-3 facts gained for 6 unexpected on the bench |
| Previous reply as context for short messages | twice the facts shown, none more relevant |
| Dropping facts never used | loses uses at the base rate |

What the data did show: a fact's own history predicts use (used in another
session, 30% used again; never used, 11%), and short messages are 35% of real
turns with only 47% of them getting any fact.

## The road, in order

1. **Verify the release**: the Release, CI and Standalone runs of the tags
   `neuron-v6.12.0` and `neurag-v1.9.1` were still running when this was written.
2. **Let the counters fill.** `shown` and the reply-based `confirmed` started on
   2026-11-16. Nothing to build; a few weeks of normal use.
3. **Run the use-rate experiment** when most recalled facts have `shown >= 2`:
   set `NEURON_FACT_USE_BONUS=0.10`, wait two weeks, compare the two halves with
   `python gray_matter/bench/ledger.py --json` (`any_use_rate_by_arm`; baseline
   20.9% / 20.8%). Adopt only on a clear difference; otherwise back to 0.
4. **Write the install procedure into `ENVIRONMENT.md`** (outside the MSIX
   container, `GM_HOME` set): today it lives only in an assistant's memory file.
5. **Show the new data in the control center**: author, shown/used counts,
   notes, the experiment's halves. Nothing of it has a screen yet.
6. **Procedure facts** (Neuron 7): start from a bench set of real task messages.
7. **Gray Matter**: extended cohesion in the smoke, a quiet daemon log, the use
   signal for Codex.
8. **With the GPU**: a frozen bench corpus for NeuRAG, then the embedder trial.

above: a step that serves none of them needs another reason to exist.

| **Who wrote it, when, and who disputed it** | A fact with no author and no date is taken as true | Author and notes are stored and shown since 6.12.0; the date is in the text only when the writer put it there | Show the fact's date beside its id when it is older than a threshold |

Not a need: more recall. Two right facts are worth more than ten plausible ones,
because the plausible ones are read too.

Each "smallest next step" is a hypothesis, not a decision: it goes through the
same measures as everything else before it is installed.

Rules that held all day: measure on all three bench sets before installing;
install before the gate's smoke when the hook changed; a fact that is not used
is not less useful — history may only add to a score, never hide a fact.

Order set by the user: polish Neuron first, then Gray Matter, then NeuRAG if it
needs it. Supersedes the open items of [TODO-2026-11-10](TODO-2026-11-10.md)
where they overlap.

**The line.** A memory that never calls a model to work, and that calibrates
itself on the real usage of whoever uses it. No extra models, no idle
rumination, no numbers or vectors handed to the model. Every step is measured
before it goes in; a step that does not move a number is not installed.

## Neuron — what is left

In order. Each one is measured on the bench (all three sets) before it goes in.

1. **A real use signal, from the Stop hook.** Today a fact counts as used when
   the next `store_turn` shares a concept with it: of 81 confirmed facts, 31
   got it by superseding, 1 by an `#id` citation, 50 by concept overlap alone.
   Explicit signals are too rare to stand alone. The hook at the end of the
   turn checks whether the reply used the fact's distinctive words, as
   `gray_matter/bench/ledger.py` already does offline, and reports it. Check it
   against the ledger before trusting it. Nothing ranks on `confirmed` until
   this is in.
2. **A calibrated score.** A logistic fit on the used/unused labels, over four
   signals (similarity, named concept, shared wording, recency). The score
   becomes a probability; recall shows a fact above a threshold and stays
   silent below it. Replaces the five hand-tuned knobs. Accepted only if the
   bench does not regress; otherwise the hand weights stay.
3. **State questions.** The newest `progress` facts next to the profile on the
   first call of a session, as gists. With 2 facts the bench gains 1; try 3.
4. **The previous turn as context.** An elliptical message ("can we release?")
   is enriched with the concepts of the last stored turn. Needs a bench set of
   sequences, not single messages.
5. **Recency and use in the score** (ACT-R base-level activation). One term.
   Depends on 1.
6. **Fact kind `procedure`.** Indexed by task type, recalled for that task and
   out of the always-shown profile. Born only from a measured outcome (gate
   green, smoke passed, a correction by the user); retired when it fails.
7. **Housekeeping.** Backfill the 169 missing gists with a cheap model; grow
   the bench past 22 messages from real transcripts.

Not doing: idle rumination, propagation across the whole graph, skills the
model writes and runs by itself.

"Neuron 7" is the name for the release where procedure recall has its own
bench set and a number.
