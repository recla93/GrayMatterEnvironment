## File modificati

### Neurag/db.py — delete_node() (riga 367-392)

**Bug**: pyturso 0.6.1 va in stack overflow C quando `delete_node()` esegue `DELETE FROM nodes WHERE id = ?` con `PRAGMA foreign_keys=ON` e FK `ON DELETE CASCADE` definite — anche se i figli sono già stati cancellati manualmente. Il C extension tenta comunque di verificare la cascade e ricorre all'infinito: `_prepare_first` → `_prepare_single_statement` → `execute` → `execute`.

**Fix**: wrappato il delete loop con `PRAGMA foreign_keys=OFF` / `PRAGMA foreign_keys=ON`.

Prima:
```python
doomed = [d["id"] for d in reversed(self.get_descendants(node_id))]
doomed.append(node_id)
for nid in doomed:
    self._conn.execute("DELETE FROM chunks WHERE node_id = ?", (nid,))
    self._conn.execute(
        "DELETE FROM node_links WHERE source_id = ? OR target_id = ?",
        (nid, nid))
    self._conn.execute("DELETE FROM nodes WHERE id = ?", (nid,))
self._conn.commit()
return len(doomed)
```

Dopo:
```python
doomed = [d["id"] for d in reversed(self.get_descendants(node_id))]
doomed.append(node_id)
# ponytail: FK off for the loop, pyturso 0.6.1 C cascade bug
self._conn.execute("PRAGMA foreign_keys=OFF")
for nid in doomed:
    self._conn.execute("DELETE FROM chunks WHERE node_id = ?", (nid,))
    self._conn.execute(
        "DELETE FROM node_links WHERE source_id = ? OR target_id = ?",
        (nid, nid))
    self._conn.execute("DELETE FROM nodes WHERE id = ?", (nid,))
self._conn.execute("PRAGMA foreign_keys=ON")
self._conn.commit()
return len(doomed)
```

## Issue trovate

### Fixato

1. **delete_node() FK cascade stack overflow** — pyturso 0.6.1 C extension ricorre all'infinito su `DELETE FROM nodes` quando `PRAGMA foreign_keys=ON` e FK `ON DELETE CASCADE` sono definite. Fix: wrappato il delete loop con `PRAGMA foreign_keys=OFF` / `ON`.

2. **BOM in .env** — `Set-Content -Encoding utf8` su PowerShell 5.1 aggiunge BOM (`\ufeff`) che corrompe le chiavi `.env`. Il parser Python le legge come `\ufeffKEY` invece di `KEY`. Fix: `.lstrip("\ufeff")` su ogni chiave parsata.

3. **Installer degrade exit** — `install.ps1:109` usciva con `exit $LASTEXITCODE` quando `gray-matter install` falliva, impedendo il fallback standalone. Fix: `if ($LASTEXITCODE -eq 0) { exit 0 }`.

4. **wire() token su URL invalida** — `cloud.py:279` scriveva il token in .env anche quando tutte le URL erano invalide. Il test B8 si aspetta `.env NON toccato`. Fix: `if token and updates:` (solo se almeno una URL è valida).

### Pre-esistente (non fixato)

**test_search_with_links_enriches** — mismatch test/implementation: il test si aspetta 2 risultati (path lessicale), ma `search()` usa il vettoriale fastembed che restituisce 3 risultati per similarità semantica.
